# Обновление базы источников и графа литературы

## Короткий ответ

**Нет, простое добавление источника в Zotero или `DoctorDisser.bib` автоматически не перестраивает граф на сайте.**

Страница не обращается к Zotero, OpenAlex, Crossref или PubMed и не запускает Python. Она загружает только два подготовленных файла:

- `data/literature-graph.json` — узлы, иерархия, внутренние цитирования и краткие метаданные;
- `data/literature-details.json` — аннотации и полные списки ссылок, загружаемые при выборе источника.

Чтобы изменение появилось на сайте, нужно обновить исходные данные, перестроить основной граф, экспортировать оба JSON и проверить результат. На GitHub Pages изменения публикуются только после попадания новых JSON в ветку `main` и успешного запуска workflow `Deploy site to GitHub Pages`.

## 1. Правила добавления источника

1. Добавьте запись в коллекцию Zotero `DoctorDisser` (`UPPVQ333`). Заполните название, авторов, год и по возможности DOI, URL и аннотацию.
2. Добавьте цитирование этой записи в `../disser-text/dissertation/dissertation_2-3-5.md` в виде `@ZOTERO_KEY`. Основной граф включает **только источники, реально процитированные в диссертации**. Остальные записи коллекции в граф не попадают.
3. Экспортируйте обновлённую коллекцию в `../disser-text/bibliography/DoctorDisser.bib`. BibTeX-ключ должен быть стабильным и уникальным: он становится `id` и `bibtex_key` узла.
4. Обновите соответствие BibTeX-ключа и восьмисимвольного ключа Zotero в `doctordisser_bibtex_zotero_map.json`. Сейчас отдельного автоматического генератора этого файла в репозитории нет.
5. Не создавайте citation-рёбра вручную по смысловой близости. Ребро `cites` должно подтверждаться ссылкой из OpenAlex, Crossref или PubMed. Направление всегда такое: `source` цитирует `target`.
6. Не выдумывайте отсутствующие аннотации, год или ссылки. Неизвестный год представляется как `null`; пустые списки и `missing_fields` означают отсутствие данных в использованных источниках метаданных.

Год влияет на порядок статей и расстояние от Положения в раскладках. Принадлежность к задаче и методу определяется главами и разделами диссертации, в которых стоит цитирование, а также правилами `SECTION_METHODS` в `build_dissertation_graph.py`. Если новый раздел ещё не включён в это соответствие, добавьте его осмысленно, а не только ради прохождения проверки.

Звёздочка работ автора и квадратик терминальной статьи вычисляются автоматически: отдельные поля для этих обозначений в исходные данные добавлять не нужно.

## 2. Пересборка основного графа в `disser-text`

Команды ниже запускаются из каталога `../disser-text/bibliography`. Сетевые шаги используют внешние API; Zotero также требует локальную конфигурацию доступа. Не копируйте ключи API и каталог `_zotero_plugin` в `Educational-Live-Demo`.

```bash
cd ../disser-text/bibliography

# Обновление снимка коллекции Zotero (сеть и локальный доступ к Zotero).
python3 export_doctordisser_zotero.py

# После ручного обновления DoctorDisser.bib и таблицы соответствия ключей.
python3 build_graph_inventory.py

# Обновление метаданных и подтверждённых списков литературы.
python3 enrich_openalex.py
python3 enrich_crossref_pubmed.py
python3 enrich_reference_metadata.py

# Построение и проверка основного графа.
python3 build_dissertation_graph.py
python3 validate_dissertation_graph.py
```

Если меняется только расположение существующих цитирований в тексте диссертации, а библиография и внешние метаданные остаются прежними, достаточно повторить два последних шага. Если меняется только основной `dissertation_citation_graph.json`, в `disser-text` повторно запускать сетевые шаги не нужно.

Сетевое обогащение использует локальные кэши. Ошибка или пробел во внешнем API не должны молча превращаться в утверждение, что у статьи нет ссылок: проверьте `graph_enrichment_summary.json`, `missing_fields` и предупреждения скриптов.

## 3. Экспорт данных для сайта

Из корня `Educational-Live-Demo` выполните:

```bash
python3 scripts/export_literature_graph.py \
  --source ../disser-text/bibliography/dissertation_citation_graph.json \
  --bibtex ../disser-text/bibliography/DoctorDisser.bib
```

Скрипт работает без сети, проверяет схему и атомарно заменяет оба файла в `data/`. Скопированный вручную основной JSON не заменяет этот экспорт: браузеру нужны оптимизированная схема, производные счётчики и отдельный файл деталей.

Не редактируйте вручную `data/literature-graph.json` и `data/literature-details.json`: следующий экспорт перезапишет такие правки. Источником истины являются библиография, текст диссертации, метаданные и `dissertation_citation_graph.json` в `disser-text`.

## 4. Что обязательно обновить при изменении числа источников

Сейчас экспортёр и браузерная проверка рассчитаны ровно на 373 источника. Если их станет 374 или больше, одного экспорта недостаточно: сначала обновите явные ограничения и ожидаемые значения по фактическому новому графу.

В `../disser-text/bibliography`:

- `validate_dissertation_graph.py`: числа узлов, источников, цитирований и связанные проверки;
- `build_dissertation_graph.py`: явные ограничения по числу источников и текст `meta.scope`, если они заданы в текущей версии скрипта.

В `Educational-Live-Demo`:

- `scripts/export_literature_graph.py`: `SOURCE_COUNT`;
- `js/literature.js`: проверка числа источников в `validate()`;
- `tests/literature_check.js` и `tests/literature_browser_check.js`: ожидаемые количества узлов, источников, рёбер, аннотаций, ссылок, авторских и терминальных работ, а также ожидаемые результаты фильтров;
- численные описания в `index.html` и `README.md`.

Количество узлов не равно количеству статей: к источникам добавляются научная проблема, Положения, задачи и методы. Число рёбер не следует угадывать — возьмите его из строки `Exported ...`, которую печатает экспортёр, и сверьте с `meta.counts`.

Если удалён источник, который использовался как конкретный пример в тесте, замените пример на подходящий существующий источник с нужными свойствами. Не удаляйте проверку только потому, что прежний идентификатор исчез.

## 5. Проверка перед публикацией

```bash
npm ci --no-audit --no-fund
npx playwright install chromium --no-shell
npm run test:literature
node --check js/literature-core.js
node --check js/literature.js
python3 -m py_compile scripts/export_literature_graph.py
```

Затем запустите локальный сайт и вручную проверьте новый источник:

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000/#literature`, найдите источник по названию, DOI и году и убедитесь, что:

- узел находится под правильными Положением, задачей и методом;
- карточка содержит правильных авторов, год, DOI/URL, аннотацию и ссылки;
- входящие и исходящие цитирования имеют правильное направление;
- при выборе остаются только его полная цепочка цитирований и пути иерархии до научной проблемы;
- «Сброс» показывает все узлы и связи;
- в консоли браузера нет ошибок.

Проверки CI не получают исходную папку `bibliography` и не пересобирают основной граф: они проверяют уже экспортированные JSON. Поэтому оба новых файла `data/literature-*.json` должны быть включены в изменение вместе с обновлёнными проверками и описаниями. Push и публикация выполняются только по отдельной команде владельца.
